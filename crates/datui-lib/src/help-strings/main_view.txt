Navigation:
  ↑ / ↓ (j/k):      Move the row cursor
  ← / → (h/l):      Move the column cursor, frozen columns included; the
                    columns scroll only when it would leave the screen
  [ / ]:            A page of columns left or right, the cursor on the
                    page's first column (Shift+←/→ too)
  { / }:            First column, last column
  g:                Go to a column by name; the cursor goes with it
  PgUp/PgDn:        Scroll pages (Ctrl+F down, Ctrl+B up)
  Home/End:         Go to first/last row (G = End)
  Ctrl+D/Ctrl+U:    Half page down/up
  ::                Go to line number (e.g. :0 Enter for top)
  f:                Find text or a regex in the view; the cursor, column
                    cursor and all, goes to the first match at or after
                    its row
  n / N:            Next / previous match from the cursor's cell,
                    wrapping round the view
  Enter:            On a row of a by query or a SQL GROUP BY, drill into
                    its rows (Esc comes back); elsewhere, inspect the row
  Space:            Inspect the row: every field, each value whole and
                    exact (Esc or Space closes). The bar's first chip
                    says what Enter does: Inspect, or Drill

Data Operations:
  /:                Query: SQL, Search or q-style
  c:                Open charts
  s:                Open the Sort & Filter sidebar (tabs: Columns, Filters),
                    on the cursor's column
  F:                Value counts of the cursor's column: each value's
                    rows, percent and a bar, with a summary
  a:                Open Statistical Analysis. In a Data Quality evidence
                    drill a is disabled; Esc returns to the observation
  p:                Open Pivot & Melt
  e:                Export data to file
  y:                Copy to the clipboard (cell, row, view or table); a
                    cell is the cursor's
  r:                Reverse sort order (sorted columns carry a direction
                    mark in the header); with no sort, reverse the row order
  R:                Reset table: clear the query, filters, sort, column
                    order, hidden columns and widths, frozen columns,
                    pivot/melt, drill-down and the applied view
  V:                Apply the best-matching view (or open the list)
  v:                Open the views list

Display:
  i:                Open Info panel (tabs: Schema, Resources, Partitions, Notes)
  #:                Toggle row numbers
  ,:                Toggle number formatting (digit grouping)
  D:                Toggle the type row under the column headers
  b:                A binary file read through a format spec: read it again
                    with another spec. Clears the query, filters and sort
  H:                CSV, TSV, PSV: read the first row as data, under column_1,
                    column_2, …; again to read it as column names. Reads the
                    file again, so the query, filters and sort are cleared
  ? / F1:           Open this help (F1 works in text fields). Esc or ? to close.

  Only the keys above are table keys: a letter with Ctrl or Alt held does
  nothing here, beyond Ctrl+F/Ctrl+B and Ctrl+D/Ctrl+U paging.

Help Navigation:
  ↑↓ (j/k):         Scroll help content
  PageUp/PageDown:  Scroll help pages
  Home/End:         Jump to top/bottom

Exit:
  Ctrl+O:           Home screen (works during a load; abandons it)
  Ctrl+Q:           Quit from anywhere (Ctrl+C too, outside a text field)
  q:                Back to the home screen when the dataset was opened
                    from it; otherwise quit (the control bar says which)
  Q:                Quit

Mouse:
  Click:            Put the cursor on the cell; on a header, its column
  Double-click:     Enter on the row
  Wheel:            ↑ / ↓, three rows a notch; the same in help, the
                    inspector and the sidebars
  Shift+wheel:      ← / →, the column cursor (a sideways wheel too)
  Click a chip:     Press its key
  Shift+drag selects text in most terminals. mouse = false under [display],
  or --mouse=false, leaves the mouse to the terminal.

While busy:
  At the plain table, q, Q, column scroll (←/→, h/l, [ ], { }), ? and F1
  act at once; Ctrl+Q/Ctrl+C quit and Ctrl+O abandons a load at once.
  Other keys are queued and replayed in order once the work is done —
  except a bare Esc, or an Enter that would drill, which is dropped; an
  Enter that would inspect waits as Space. At most 32 keys are held,
  and held keys die with the screen they were typed at. At the loading
  screen nothing is held: the allowed keys act, the rest are dropped.
  While a view is being applied, Esc stops it and keeps the table as it was.
  While a find reads, Esc (or Ctrl+O) stops it, and the n / N typed
  behind it, and the cursor stays put.
  The mouse is never queued: the wheel across and the busy bar's chips act
  as their keys do; the wheel down and a click on the table are dropped.

Wide tables:
  ] starts the next page at the first column not shown whole, so a column
  cut at the edge is read whole there; the last page is always full, and
  [ right after ] goes back to the page it left. The bar says where the
  column cursor is: col 43 of 300, counting the columns shown, frozen
  first and hidden ones not at all.

Wide columns:
  A column keeps the width it was first drawn at, so paging and scrolling
  move nothing; a query, sort, filter or drill learns it again from the
  first page it shows. Text, lists, structs and names get at most two fifths of
  the window (32 cells at 80 columns, 48 at 120); a numbers column widens
  to its widest number yet seen. Set a width in Sort & Filter (s): < and > narrower and
  wider, f fits the rows on screen, w back to automatic.
  A value or name cut short at the edge of its column ends in …; Space shows
  the row's values whole. A line break in a value shows as ¶, a tab as »
  and another control character or a direction mark as ¤ ($, > and ? in
  ASCII). A number is
  cut only as the first scrolling column with no room for it; otherwise it
  waits, whole, for the scroll.
  Frozen columns (L in Sort & Filter) sit left of │. When it shows as ┆, the
  window is too narrow for them all: the ones that do not fit scroll after
  it, and are frozen again when there is room.

Empty cells:
  A directory of Parquet files may hold files that disagree, so an empty cell
  says which kind of empty it is:
    ∅ (ASCII ~)    null: the data's own null
    · (ASCII .)    absent: the file this row came from has no such column
    ≠ (ASCII !)    conflicting: the file holds the column in another type,
                   so it was not read from that file
  A column whose name carries a * mark is not in every file, or the files
  disagree on its type. The Info panel's Schema tab says where the schema
  came from.
