Data Quality checks the rows of the shared sample and
reports what it found. Setup comes first: every
setting a run takes, staged until Enter runs it.
Nothing in Setup reads the data; only Run does.

Setup:
  Rows & sample:  The sample every tool reads
  Columns:        Text read as time, time roles, the
                  intervals between them, and what
                  each column must hold
  Study:          Grain, expected windows, comparison,
                  values, latency threshold, and the
                  window intervals go in
  Read:           What Run will read, before it reads

  ↑ / ↓, Tab:   Move between rows
  ← / →:        Change a short list's choice
  Space:        Open the row: the Sample form, a
                list (type to narrow), Time roles,
                Intervals, Column intent or Expected
  s:            The Sample form; its Enter applies
                to Setup and returns there
  p:            The access plan: what a run reads
  d:            Release the rows runs kept and a
                full scan's local copy, named on the
                Read rule; the next run that would
                reuse them reads again
  Enter:        Run, from any row. A full read asks
                first; the report on screen or in the
                session cache is shown, not read again
  Esc:          Discard every staged edit

Text as time:
  A text column that holds times is read through a
  format you choose, for grain and time roles only;
  every other check sees the text. Each format says
  how many values on screen it reads. Values it does
  not read are counted as Unparsed times, never as
  missing. A format with an offset (%z) reads each
  value as an instant in UTC; beside one, a time
  with no zone is taken as UTC.

Reuse:
  A run keeps the rows it read. Roles, text as time,
  compare, row chunks and a coarser window of a
  counted grain use them and read nothing; a new
  partition or a finer window is counted once. A new
  seed, size or scope reads a new sample. Read in
  Setup says which, before Run. Kept rows last the
  session, until memory runs short, d in Setup or
  opening the dataset again releases them.

  A full scan of a remote dataset that fits
  quality_local_copy_mb and the free disk fetches
  each object once into the cache directory; every
  pass, and every later full scan, reads that copy.
  Read says so before Run, or why the passes go to
  the source. d, opening the dataset again and
  quitting remove the copy; a cancel or failure
  while it is fetched removes what was copied.

Time roles:
  ↑ / ↓:        Choose the role
  ← / →:        Choose its column
  Enter:        Done
  Esc:          Put back the roles as they were

Intervals in Setup:
  Every start and end the roles make, the suggested
  ones first: event to published, received or
  processed; period end to published; published to
  received; received to processed; valid from to
  valid to. Setup names a role in no interval.

  ↑ / ↓:        Choose the pair
  Space:        Measure it or not; ← / → too
  Enter:        Done
  Esc:          Put back the pairs as they were

Column intent:
  What a column must hold, declared: part of the
  key, required, read as a whole number or decimal,
  one of a set of values, or within a range. Run
  counts what breaks each rule as a problem, from
  the rows it reads; on a full scan the key is one
  more pass. On a sample a key finds repeats among
  the sampled rows only. Nothing here reads.

  ↑ / ↓:        Choose the column
  Space:        Declare its intent in a form
  Enter:        Done
  Esc:          Put back the intent as it was

  In the form, Tab or ↑ / ↓ move between rows, Space
  ticks Key or Required, ← / → change Read as,
  Enter applies and Esc drops the edit. Allowed
  values are separated by commas and match exactly,
  case and spaces included; quote one that holds a
  comma: "a, b". A range bound is a number, a date,
  or a date and time, and counts as in range; a
  date alone as a time's maximum takes its day.

Expected in Setup:
  With a time-window grain: which windows rows
  belong in, every one or weekdays only, From and
  Before a date or UTC time (blank: the first or
  last window found). Only then is a window with no
  rows a gap. Changing only this reads nothing.

  ↑ / ↓, Tab:   Windows, From, Before
  ← / →:        Choose the windows
  Enter:        Done
  Esc:          Put back Expected as it was

Pages:
  Overview:     The report: the verdict, its coverage,
                then problems, notes and clean
                columns, most important first
  Columns:      Each column's mark and findings; Enter
                opens its detail, Enter again returns
  Segments:     Each segment's rows, null cells and
                largest change. Needs a Grain
  Trends:       Each column's measure across segments
  Intervals:    The time between two roles, in each
                segment. Needs time roles

Keys on the report:
  ← / → (h/l):  Previous or next page
  1 - 5:        Overview, Columns, Segments, Trends,
                Intervals
  e:            Setup
  ↑ / ↓ (j/k):  Move, or scroll a tall finding
  PgUp/PgDn:    Page; Home/End jump to either end
  Enter:        Open a finding, then its rows. On an
                empty page, open the setting it needs
  c / t:        Overview: only one column's or one
                type's findings
  o:            Overview: ranked, by rows, by rate
  s:            Setup, with the Sample form open
  v:            View the sample's rows; Esc returns
  p:            Show the access plan: what a run reads
  r:            On a sample, run again with a new
                seed
  x:            Export the report to JSON or
                Markdown; nothing is read
  Tab:          Move between the result and the tools
  Esc:          Back one level: all findings again,
                then close
  ? / F1:       Show this help

Coverage, under the verdict:
  Checks:       How many ran over every row (exact),
                a sample (sampled) or file footers
                (metadata); how many had nothing to
                look at (skipped) and how many this
                run could not answer (unavailable)
  Rows:         The rows read of the total, and the
                rows the run's reads passed through
  Limits:       Why a check was unavailable, thin
                segments, footers not all read, and
                time roles that form no interval

A finding's rows:
  Enter on a finding shows the rows it counted from
  the rows the run kept: a sample's, or every row a
  sample covered. Duplicate rows open copies
  together; Numbers as text opens the values that do
  not parse. A full scan keeps no rows, and a sample
  may be released: then Enter shows what reading
  them takes, and only Enter there reads. Grouped
  columns list each column's count; the rows with
  any of them are a range, not a sum.

While a run reads:
  The progress names the stage, whether it reads the
  source, and the rows seen where the read counts
  them. Esc cancels: a streamed read, a full run's
  passes included, stops at its next batch. A read
  that cannot stop is said to be finishing, in the
  header and in Setup, until it ends; Run and every
  other read wait for it. The last report stays.

Segments:
  Enter:        A segment's columns beside the one it
                is compared with, largest change first
  o:            Largest change first, or back in order
  b:            Compare with the highlighted segment

Trends:
  Enter:        A line's bars: span, segments, rows
                sampled of counted, rate, 95%
                interval, and the bar before
  ↑ / ↓:        In the bars, the next bar
  m:            Next measure
  w:            Stage a coarser window in Setup,
                for segments the sample reached
                thinly or not at all
  g:            The expected windows with no rows:
                empty by exact count, not sampled,
                or out of scope
  Esc:          Back to Trends

Intervals page:
  Enter:        An interval's detail: its ends, the
                rows with both, missing and unread
                ends, negative and zero durations,
                percentiles and breaches. Enter
                there shows the rows behind the count
                under the cursor: a sample's from the
                rows the run kept
  Esc:          Back to the list
  A breach is duration > threshold, strictly, out of
  the rows with both ends. Valid from to valid to
  counts periods with no end as open, and an end
  before the start as ending first.

What a sample can say:
  A rate, such as missing values, stands for the
  whole. A distinct count does not, so Nearly unique
  needs every row read. On Segments a change is named
  only past sampling noise; Trends pools segments and
  shows smaller ones. A finding's rows are the rows it
  counted, from the sample when it read one. Missing
  and mistyped columns come from the file footers and
  cover the whole source. Only reading every row asks
  first.
