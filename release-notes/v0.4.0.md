## What's changed

### Data quality

- Analysis now includes a planned data-quality profile with explicit scope,
  grain, compute budget, comparison, access estimate, column observations,
  segment changes and user-assigned lifecycle latency studies.
- Data-quality scopes can target the current view, loaded source, view row
  range, source files, partition value or time range.
- Profiles are measured at whole-dataset, file, partition, row-chunk, or
  hourly, daily, weekly and monthly time-window grain. A window is cut at the
  same place whether the run sampled or scanned it, and a sampled run measures
  everything an exact run does.

### Home screen

Run `datui` with no path. It lists recent datasets, the current directory,
your configured data directories and the buckets your credentials reach, with
rows, columns and size shown before you open anything. Type to filter by name
or column name; the search also walks below the working directory. Ctrl+O
returns here from anywhere.

Recent datasets are grouped under the directory or bucket prefix each lives in.
Enter on a place row browses there, and Delete on it forgets every recent under
it. The directories of recent datasets are no longer sections of their own, so
the top level is at most Recent, the current directory, Cloud, your configured
directories and Elsewhere.

A section titled by a path says why it is there in a chip beside its count,
`current directory` or `configured`, and the note at the end of the rule says
only how it is doing. A dataset opened from a bucket shows its rows, columns and
label under Recent on the next launch, a place row says what datui last found
it to be, and a tall terminal gets a blank line between sections.

Opening a dataset while a row count is running opens it. The count answers by
jumping to the end, which started a buffer read that cancelled the open — and the
open's answer was then discarded when it arrived, leaving the spinner up and the
file never opened for the rest of the session. The same held for an export and an
analysis. Background work now holds the token a read would invalidate, and the read
waits for it.

A folder is offered as one dataset only when its files hold the same table. A
database exported one Parquet file per table was read as a union of all of them,
with a row count that was their sum; datui now compares the files' columns and
leaves such a folder as a directory to look inside. Datasets whose columns grew
over time are unaffected.

What the home screen offers and what datui can open are one list. `.psv` and
`.xlsb` files opened but were never listed; a `README.txt` was listed and then
refused, and is no longer offered. A folder of `.tsv` or Excel files is not
offered as one dataset either, because reading many of them as one table is not
something datui does yet.

A folder is classified from its whole listing rather than its first eight
entries, so the answer no longer depends on the order the filesystem returns
them: a folder of Parquet files with a `_metadata.json` among them was one
dataset locally and a plain directory in a bucket. The files a job leaves beside
its output — `_SUCCESS`, `_committed_*`, `.crc` — no longer count toward what a
folder holds, by the same rule on every route: a leading `_` or `.`, which also
covers a repository's own `.git` and a project's `.venv`.

A folder's label says what is directly inside it — `12 parquet`, `3 csv`,
`mixed`, `dir` — rather than naming what Enter will do with it, so a label that
is wrong about the second is still true about the first. The details pane carries
the whole tally on a `holds` line, including the files skipped as a writer's own,
by name. A folder of separate tables reports the union of their columns, and no
row count, instead of neither — for the session that measured it, since a
directory's own timestamp cannot see a file inside it being rewritten in place.

A folder of Parquet files opens as one dataset when every file's columns are in
the widest file's, which is the shape schema evolution makes. This replaced a
containment ratio against a threshold: a dataset grown from five columns to
fifty with one dropped along the way scored below a folder of unrelated tables
sharing a key, so no number over column overlap could separate the two. A folder
that fails the test now is not refused, only a keystroke further away — which is
what the doors below are for.

Every folder has two doors, and neither depends on the label being right. → goes
inside any folder, whatever it is labelled, so one partition or one file can
always be reached. The first row in there — `<folder> (all files)`, or `(all
partitions)` for a hive folder — opens the whole folder, local or in a bucket, so
a label that is wrong about what a folder holds costs a keystroke rather than
access to it. That row used to exist in a bucket only, and there only for the
folders datui had already called datasets, which is the same judgement made
twice.

That row does not refuse. A folder of more than one format is read as the
commonest of them — a thousand CSVs and one stray JSON is a folder of CSVs — and
the Notes tab says what it passed over. Files written with no extension, as Spark
and GBIF write part files, are read by what their first bytes say; such a folder
listed nothing and opened nothing before. A prefix of CSV or NDJSON in a bucket
is read with that reader, instead of reporting a problem with your credentials.
What is still refused is a prefix holding nothing datui has a reader for, and it
names what is there.

The rule that decides reaches every format, not just Parquet. A folder is one
table when every file's columns are within the widest file's — read from a
Parquet footer, a CSV header line or an NDJSON object's first keys, whichever the
folder holds. A folder of forty unrelated CSVs was labelled `40 csv`, Enter
promised one table because nothing had looked, and the read then refused it with
a Polars error; now Enter steps inside it and the row in there reads the union.

Parquet, CSV and NDJSON files that disagree are read as the union of their
columns rather than refused, with a row from a file without a column reading
null. A column typed by inference — `amount` an integer in one file and text in
the next, because one row said `N/A` — is widened rather than failing the folder.
The Notes say which of the two happened, because a column silently turned to text
sorts and filters as text. A folder of headerless files is not offered as one
table at all — every file's first row would become column names — and says to
pass `--no-header`. Arrow, Avro, ORC and JSON keep their columns nowhere
cheap to look at before the open, so they are neither judged nor unioned, and
still refuse when their files differ.

The control bar says which key does which, for the row under the cursor: `Open
all` reads the whole folder, `Inside` steps into it, `Open` loads a file, `Look`
finds out first. Where Enter and → do the same thing, only one is offered. On a
folder Enter steps into, the details pane names where the whole of it can be
read.

Polars' resolved query plan no longer reaches the error modal: four lines of
`FAILED HERE RESOLVING THIS_NODE` around one fact worth keeping, which is the
file the read stopped at.

`datui <folder>` does what Enter on that folder's row does, and needs no flag. A
directory was `Unsupported file type` without `--hive`, while pyarrow, Polars,
pandas and Spark all open one. A folder that is one table opens as one; a folder
of separate tables, of several formats, or with no data directly inside opens
the home screen browsed into it, one keystroke from either a file or the union.
`--hive` is unchanged: it is for a glob, and for forcing partition columns on a
layout that does not say so itself. Options that say how to read the files —
`--no-header`, `--skip-rows`, `--null-value` — are taken as the answer rather
than second-guessed, so such a folder is read as one table rather than judged by
a reading datui was told not to make.

Working out which of those a folder is reads footers, which on a large one takes
a few seconds. That happens after the first frame, on a worker: the screen names
the folder it is looking at and keeps its spinner, where before it was blank for
the whole wait with no key that worked.

Opening a row on a network share that nothing has looked at yet looks at it first,
on a background thread, so a lake table there is recognized rather than read as one
table. A share that never answers no longer freezes the interface, and Ctrl+O puts
the wait down.

A Delta, Iceberg or Hudi table is labelled `delta`, `iceberg` or `hudi` and is not
offered as a folder of Parquet files. Read that way its log is ignored: deleted
rows come back, every rewritten version is counted, and a compacted table is read
twice over. Enter goes inside, where the files can be opened one at a time — and
where the `(all files)` row reads them all together, labelled as what they are: a
note in the panel, and `not the Delta table` beside the row count, because that
count includes rows a delete tombstoned and versions an update replaced.

A folder in a bucket is looked into where the cursor rests. Verification took the
first forty-eight folders of each listing, once, so a bucket of two hundred
prefixes had forty-eight labelled and the rest reading `dir` for the session
however long you spent on them — and paging straight past those forty-eight spent
every request on rows nobody saw. Azure prefixes are verified too; before, a
prefix of separate tables there opened as one table.

A folder's row lists every column any of its files has, not the first file's. A
dataset whose columns grew over time reported the shape it was born with, so
searching the home screen for a column added later did not find it. A folder too
large to read every footer of reads a spread of it instead, and marks the count
as the floor it is: `? × 39+`.

The column count is the columns you get when you open it. Nested data was counted
by its leaves, so a file with one struct of three fields said `columns 4` above a
schema list of two.

### Cloud sources

- Every object store is a row under `CLOUD` on the home screen. Enter lists its
  buckets; the title bar shows where you are.
- `[[cloud.sources]]` adds more stores, with keys read from environment
  variables you name. `s3://<name>@bucket/key` opens from a named
  S3-compatible server, so two servers can share bucket names.
- Bucket lists from the last run show at once, sources are listed side by
  side, and Ctrl+R lists again.
- AWS profiles work: `AWS_PROFILE`, `credential_process`, and SSO or roles
  through the AWS CLI. Every profile that can log in is its own source.
- MinIO client aliases, `MC_HOST_<alias>` and s3cmd's config are sources too,
  with no datui config.
- Azure Blob Storage: after `az login` or `Connect-AzAccount`, every storage
  account you can see is listed, and `abfss://` URLs open. Service principals,
  workload identity, connection strings, keys and SAS tokens work too, and
  `kind = "azure"` sources name one account. An Owner or Contributor with no
  data role reads with the account key, as the Portal does.
- The install script installs into `~/.local/bin` where there is no `sudo`, as
  in Azure Cloud Shell.
- Secrets from elsewhere: `secret_command` (`pass`, `op read`), a Google
  `credentials_file`, and `[cloud] env_files` for a project's `.env`.
  `[cloud] instance_identity = true` uses the VM's own identity on EC2, GCE
  and Azure; Cloud Run and Azure App Service are found without it.
- The built-in public dataset catalog is emitted by `--generate-config` as editable
  structured entries with names, descriptions, publishers, licenses and homepages.
- Public datasets are built in: NOAA weather, Bitcoin and Ethereum, OpenAlex,
  Overture Maps, Google Open Buildings and BigQuery's samples, each with its
  publisher and license. Public buckets open with no login, and a login from
  elsewhere no longer blocks them. `public = true` sources keep your own list.
- Each S3 bucket is read in its own region.
- Cloud folders are labelled by what they hold, the way local ones are, and a
  folder of partitions, or of Parquet files that all have the widest file's
  columns, opens as one dataset.
- A remote dataset of many files is counted from its footers and reads only
  the files a page needs: Bitcoin's 1.4 billion transactions open in seconds
  and End reaches the last one. Files whose columns or nested fields changed
  over time read into the newest schema. End on one that has not been counted
  yet says it is counting, and says so if the count fails, rather than leaving
  the view where it was with no explanation.
- Google Cloud lists every project you can see, each with its buckets, and
  works with only `gcloud auth login`. Each `gcloud` configuration with
  another account is its own source.

### New look

- Default palette after Tokyo Night, dark and light. Every color is still a
  config key.
- Column headers take their column's color; a second header row names each
  type (`D` toggles).
- The current row is tinted with a rail instead of reversed video.
- Keys in the control bar are chips. Nulls are `∅`. Off-screen columns show
  as `+10 →`.

### Remote Parquet

- S3 and GCS objects are read one row group at a time. Paging inside a row
  group makes no requests; the first row group used to be fetched twice on
  open and again on every page.
- The buffer is sized in bytes before it is read, so a wide table stays within
  `max_buffered_mb`.
- A filtered remote table reads a page at a time and takes its row count from
  a short read instead of a second pass.
- Counting the rows of a dataset whose files disagree on a column's type no
  longer crashes: filtering, querying or resetting one took the whole app down.
- A dataset of many Parquet files shows every column any of its files has, not
  just the ones in the file its schema was read from. Types that differ across
  files widen where that loses nothing; where it would not, the column takes the
  type most of its rows have and is left unread in the other files. The Info
  panel's Schema tab says which footers the schema came from, and a file whose
  footer cannot be read no longer stops the dataset from opening.
- Exporting a dataset whose files disagree can add a column naming the file each
  row came from. No format has "absent", so without it a cell the file never had
  and a cell the file left empty both write as null.
- A **Notes** tab in the Info panel says what datui noticed about the data while
  reading it: a column that is not in every file, files that disagree on a type,
  a file whose footer could not be read. Each note says what it is based on, and
  none of them costs a read of its own. When there is something to note, the
  `i` key takes a quiet accent until you open the panel.
- An empty cell in such a dataset says which kind of empty it is: a null the
  data holds, a column the file was written without, or a column the file keeps
  in another type. A mark after a column's name means it is not in every file.
  The distinction holds after a filter and a sort.

### Typing while busy

- Keys typed during a load or query are queued and replayed in order instead
  of dropped.
- Ctrl+Q quits from anywhere. Ctrl+C copies in a text field.

### Python

- Works with Python `polars` 1.38 and later, built for 1.43. A plan the wheel
  cannot read, such as a join from 1.44, is refused with a message; passing a
  file path works with any version.
- `datui.view(lf)` now reads Polars' binary plan format. It had been falling
  back to the deprecated JSON format.

### Fixed

- A sidebar filter or sort no longer discards the query you just ran.
- Charts are prepared in the background, so a large chart no longer freezes
  the screen.
- Home after End showed the wrong rows.
- A folder's label no longer depends on where it sits in the listing. datui
  looked inside the first 64 folders of a directory and called every identical
  one after them `dir`. No listing looks inside a folder now: one it has not
  looked into reads `…`, and the rows on screen are labelled as you scroll to
  them, the highlighted row first.
- The home screen's bucket list ignored `AWS_ENDPOINT_URL` and
  `--s3-endpoint-url`.
- Nulls sort last in both directions.
- `sidebar_border` and `table_selected` had no effect.
- Quitting during a bucket listing could print a Tokio panic.
- A folder of two CSV and two Parquet files was labelled `2 csv · 2 parquet` and
  opened as Parquet: the label and the reader broke a tie differently.
- <kbd>→</kbd> on a remote file with an extension datui has no reader for —
  `s3://bucket/data.dat` — went into an empty prefix listing with no explanation.
- Stepping into a folder and back out no longer erases its label for the session.
- The `(all files)` row was behind the `cloud` feature, so a build without it had
  no second door at all, local folders included.
