Every field of the table's current row, and the focused field's whole value.
It opens on the field of the table's column cursor. The title counts the
rows, Row 3 of 20, and inside a drill-down names the group: Row 3 of 20 ·
region=north. The footer offers only the keys that act now.

The fields:
  ↑ / ↓ (j/k):      Move between fields
  Home / End:       First and last field
  PgUp / PgDn:      A page of fields
  ← / → (h/l):      Previous and next row; the table's cursor moves with it
  Tab:              Move into the value, to scroll and find in it
  Enter:            On a group's row, its rows, as at the table. Else open a
                    struct, a list, or text holding a JSON object or array;
                    or read a field the table's rows do not hold (hidden and
                    binary columns)
  r:                On a group's row, read a field the rows do not hold
  y:                Copy the focused value as its view shows it
  Y:                Copy the whole row as one JSON object
  e:                The value's next view, where it has more than one
  w:                Word wrap or hard wrap for long text
  o:                Open the value in another program
  f:                Nulls: shown or hidden (null and empty fields);
                    comparing, only the fields that differ
  s:                Order: the table's, A-Z, or nulls last
  c:                Compare: a column for the next row, or the pinned one
  m:                Pin this row to compare others with; again to unpin
  /:                Find a field by name, then by value: type to narrow,
                    Enter or ↓ keeps the list narrowed, Esc clears it
  ? / F1:           Show this help (in a find line ? types; use F1)
  Esc / Space:      Close; Esc clears a find first

The value, after Tab:
  ↑ / ↓ (j/k):      Scroll a line
  PgUp / PgDn:      Scroll a page
  Home / End:       Top and end, at once however long the value
  /:                Find in the value; n and N go to the next and last place
  e, w, y, o:       As in the fields
  ← / → (h/l):      Previous and next row
  Esc / Tab:        Back to the fields; Esc clears a find first

What it shows:
  The pane shows what is stored, not the table's preview: a float is the
  decimal that reads back to it exactly, a datetime keeps every digit of its
  unit and its zone's offset. When the table rounds or groups a number, the
  line under it says what the table shows.
  Text shows its length, its lines, and spaces at either end, and wraps
  between words. Text that parses as JSON is indented, with e for Raw and
  Escaped. A long value's rule says where the pane is: lines 41-73 of
  4,000 · 1%.
  Empty text lists as "" and empty bytes as 0 bytes · empty. A null shows
  as ∅ null, never as an empty string; ∅ (null), · (absent) and ≠
  (conflicting) mean what they mean in the table. The fields' rule counts
  the nulls and empties.
  Bytes show their size and, where their first bytes say, what they are:
  PNG, JPEG, GIF, PDF, gzip, zstd, zip, Parquet, Arrow. UTF-8 bytes read as
  text; gzip and zstd as the text they hold, up to 64 KB. e cycles Text,
  Hex and Escaped.
  Lists and structs show one item per line, with text quoted.
  On a wide terminal the fields and the value sit side by side, and the
  fields flow into columns.
  For a dataset a collection documents, the lines under the value say
  what the field means and, when the documentation lists the value,
  what it stands for: AWDR = Average daily wind direction (degrees). A blank
  flag reads its blank entry.

Compare:
  c puts the next row's values beside this row's, and Δ (* in ASCII) marks
  the fields that differ; the rule counts them. At 240 columns and wider the
  row before is shown too: previous, this, next. m pins a row, so each row
  moved to is compared with it. f then lists only the differences.

Nested values:
  Enter opens a struct's fields, a list's items or a JSON document's keys and
  items as a list of their own, one level down. The title shows the path from
  the row: each field, key or [index] opened. A list of structs, or a JSON
  array of objects, is a table with a column per field. Only the items on
  screen are read, so a list of a million items opens at once. JSON text over
  64 KB is parsed in the background. Text over 4 MiB, or text that turned
  out not to be JSON, is not opened.

Inside a level:
  ↑ / ↓ (j/k):      Move between items
  Enter / → (l):    Open the focused item
  Esc / ← (h):      Up a level; at the row, Esc closes
  y:                Copy the focused item: text as itself, a JSON object or
                    array indented
  Space:            Close

Copy:
  y copies the value as the pane shows it: exact numbers, lists and structs
  as JSON, indented JSON in the JSON view, the text bytes hold in their Text
  view, other bytes as base64, a null as empty. Y copies the row as JSON;
  fields not read are left out and the message counts them. Both use the
  same clipboard as the copy dialog (y at the table). A value over the
  osc52 limit ([clipboard] osc52_limit) is refused.

Open:
  o writes the value to a read-only temporary file named for its kind
  (.json, .txt, .png, .bin, ...) and opens it. Text goes to $VISUAL, $EDITOR
  or $PAGER (else less; on Windows the system's opener), which has the
  terminal until it exits; images and documents go to the system's opener.
  Nothing is read back.

Fields not in the table's rows:
  Columns hidden in Sort & Filter, and binary columns, are not read with the
  table's rows. They show as not read until Enter reads them, for this row.
  While the focus stays on that field, each row moved to is read too. The
  read checks it found the same row; a query whose sort leaves ties may
  order them differently on a second read, and the pane says so.

In the table, a line break shows as ¶, a tab as » and another control
character or a direction mark as ¤ ($, > and ? in ASCII terminals). The
inspector breaks the lines and spaces the tabs; escaped, it names every
invisible character.
