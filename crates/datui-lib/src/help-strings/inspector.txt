Every field of the table's current row, and the focused field's whole value.
It opens on the field of the table's column cursor. The title counts the
rows, Row 3 of 20, and inside a drill-down names the group: Row 3 of 20 ·
region=north. The footer offers only the keys that act on the focused field.

  ↑ / ↓ (j/k):      Move between fields
  Home / End:       First and last field
  ← / → (h/l):      Previous and next row; the table's cursor moves with it
  PgUp / PgDn:      Scroll a long value
  Enter:            Open a struct, a list, or text holding a JSON object or
                    array; show more of a long value; or read a field the
                    table's rows do not hold (hidden and binary columns)
  y:                Copy the focused field's exact value
  e:                Show text or bytes escaped (\n, \t, \\, quotes) or as
                    itself
  /:                Find a field by name: type to narrow, Enter or ↓ keeps
                    the list narrowed, Esc clears it
  ? / F1:           Show this help (in the find line ? types; use F1)
  Esc / Space:      Close; Esc clears a find first

The value:
  The pane shows what is stored, not the table's preview: a float is the
  decimal that reads back to it exactly, a datetime keeps every digit of its
  unit and its zone's offset. When the table rounds or groups a number, the
  line under it says what the table shows.
  Text shows its length, its lines, and spaces at either end. Empty text
  lists as "" and empty bytes as 0 bytes · empty. A null shows as ∅ null,
  never as an empty string; ∅ (null), · (absent) and ≠ (conflicting) mean
  what they mean in the table.
  Lists and structs show one item per line, with text quoted. Binary shows
  as a hex dump, or escaped as b"...".
  A long value shows its first 16 KB of text (4 KB of bytes); Enter shows
  as much again each time. The last line counts the whole value: the lines
  of a hex dump, or the lines shown then the chars not yet shown.
  The fields take the rows they need when they all fit above a short value;
  a longer list takes half the height.

Nested values:
  Enter opens a struct's fields, a list's items or a JSON document's keys and
  items as a list of their own, one level down. The title shows the path from
  the row: each field, key or [index] opened. A list of structs, or a JSON
  array of objects, is a table with a column per field. Only the items on
  screen are read, so a list of a million items opens at once. JSON text over
  64 KB is parsed in the background. Text over 4 MiB, or text that turned
  out not to be JSON, is not opened: Enter shows more of it.

Inside a level:
  ↑ / ↓ (j/k):      Move between items
  Enter / → (l):    Open the focused item
  Esc / ← (h):      Up a level; at the row, Esc closes
  y:                Copy the focused item: text as itself, a JSON object or
                    array indented
  Space:            Close

Copy:
  y copies the whole value, whatever the pane shows: exact numbers, lists
  and structs as JSON, binary as base64, a null as empty. It uses the same
  clipboard as the copy dialog (y at the table). A value over the osc52
  limit ([clipboard] osc52_limit_kb) is refused before it is formatted.

Fields not in the table's rows:
  Columns hidden in Sort & Filter, and binary columns, are not read with the
  table's rows. They show as not read until Enter reads them, for this row
  only. The read checks it found the same row; a query whose sort leaves
  ties may order them differently on a second read, and the pane says so.

In the table, a line break shows as ¶, a tab as » and another control
character or a direction mark as ¤ ($, > and ? in ASCII terminals). The
inspector breaks the lines and spaces the tabs; escaped, it names every
invisible character.
