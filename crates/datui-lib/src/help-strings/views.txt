A view saves a query, filters, sort, column layout and pivot/melt, and
applies them to datasets that match by path or schema.

Views list:
  ↑ / ↓ (j/k):      Move in the list
  Enter:            Apply the selected view
  s:                Save the current state as a view (an untouched table
                    has nothing to save, and s says so)
  e:                Edit the selected view
  d:                Delete the selected view, after confirming
  i:                Show how the selected view's score was computed
                    (Esc closes the score view)
  ? / F1:           Show this help (F1 works in text fields)
  Esc:              Close

  The score mark says how well each view fits the open dataset, and the
  applied view carries a check mark. The Match column says why a view fits.
  V at the table applies the best view that matches; when none does, V
  opens this list instead.

Save and edit form:
  Tab / Shift+Tab:  Move between rows (↑/↓ outside the description)
  Enter:            Save. In the description Enter types: Tab out of it,
                    then Enter
  Ctrl+J:           Save from anywhere, the description included; so does
                    Ctrl+Enter, on a terminal that tells it from Enter
  PgUp / PgDn:      Move five lines in the description
  Space:            Expand or collapse Matching; toggle schema match
  Esc:              Back to the list, discarding edits

  Name is required and starts as the file's name. The Matching section
  holds the optional criteria: exact path, relative path, path pattern and
  filename pattern (glob-like), and schema match (column names). Schema
  match starts enabled — it is what carries the view to the next table
  with these columns.

  Editing changes a view's name, description and matching. Its saved
  settings follow the table only while the view is the one applied, so
  renaming a view never overwrites what it carries.

Matching:
  V and [templates] auto_apply only apply a view one of whose rules fits
  the open file; this list shows every view, ranked. Matches combine, so a
  view fitting by relative path and exact schema outranks one fitting by
  exact path alone. A dataset whose columns merely include a view's scores
  low — below a pattern match — and how often and how recently a view was
  used adds points.

Delete confirmation:
  Enter (d / D):    Delete
  Esc:              Cancel
