Data Quality checks the rows of the shared sample and
reports what it found. The header says which rows were
checked and whether they were a sample.

Pages:
  Overview:     The report: problems, notes and clean
                columns, most important first
  Columns:      Each column's mark and findings; Enter
                opens its detail, Enter again returns
  Segments:     Each segment's rows, null cells and
                largest change. Needs a Grain
  Trends:       Each column's measure across segments,
                and the time between dates
  Plan:         What the next run reads, and how it
                splits and compares the rows

Keys:
  ← / → (h/l):  Previous or next page
  1 - 4:        Overview, Columns, Segments, Trends
  e:            Go to the Plan
  ↑ / ↓ (j/k):  Move, or scroll a tall finding
  PgUp/PgDn:    Page; Home/End jump to either end
  Enter:        Open a finding, then its rows. On an
                empty page, open the setting it needs
  s:            Choose the sample every tool reads
  v:            View the sample's rows; Esc returns
  p:            Show the access plan: what a run reads
  r:            Rerun with a new sample seed
  Tab:          Move between the result and the tools
  Esc:          Back one level; from the Plan, close
  ? / F1:       Show this help

The Plan:
  ↑ / ↓:        Move between fields
  Space:        Open the field: the Sample form, the
                Time roles, or a list (type to narrow)
  Enter:        Run, from any field
  Esc:          Put back the plan the report used
  An edited plan waits for Enter. Until then the
  report keeps the plan it was measured with.

Time roles:
  ↑ / ↓:        Choose the role
  ← / →:        Choose its column
  Enter:        Done
  Esc:          Put back the roles as they were

Segments and Trends:
  Enter:        A segment's columns beside the one it
                is compared with, largest change first
  o:            Largest change first, or back in order
  b:            Compare with the highlighted segment
  m:            Next measure on Trends

What a sample can say:
  A rate, such as missing values, stands for the
  whole. A distinct count does not, so Nearly unique
  needs every row read. On Segments a change is named
  only past sampling noise; Trends pools segments and
  shows smaller ones. A finding's rows are the rows it
  counted, from the sample when it read one. Missing
  and mistyped columns come from the file footers and
  cover the whole source. Only reading every row asks
  first.
