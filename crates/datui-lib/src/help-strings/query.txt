Keys:
  Enter:            Run the query (reopening / restores the last query,
                    selected: typing replaces it, arrows edit it).
                    On the tab bar, Enter returns to the input
  Ctrl+T:           Next mode: SQL, Search, q-style (from the input too)
  Shift+Tab:        Input to the tab bar and back
  Tab:              SQL: complete a column name or df; again for the
                    next match. Search, q-style: to the tab bar
  Alt+Enter:        SQL: start a new line
  ← / → (h/l):      On the tab bar: switch mode
  ↑ / ↓:            Earlier and later queries from the history
                    (Ctrl+P / Ctrl+N too; each mode keeps its own).
                    In SQL over several lines, they move between lines first
  Ctrl+U / Ctrl+K:  Delete to the start / end of the line
  Ctrl+Z / Ctrl+R:  Undo / redo
  Ctrl+J:           Run, the same as Enter
  F1:               Show this help (works from the input)
  Esc:              Close

/ opens on SQL, or on the active query's mode.
[query] default_mode in the config chooses another starting mode.

Running a query — or clearing one — starts a fresh view: sidebar filters,
sort, frozen columns and pivot/melt are dropped. This is deliberate; apply
them after the query.

The prompt stays open until the query's first rows are in. A query that
fails on the data is not applied: the reason shows under it, the table
keeps what it showed, and the query is there to fix.

SQL:
  The SQL the bundled Polars supports, not the full SQL standard, over one
  table, df: the group's rows while drilled into one, the pivot or melt
  result while one is in effect, otherwise the data as loaded. Never the
  sidebar filters or sort, nor the previous statement's result.
  Example: SELECT carrier, COUNT(*) AS flights FROM df GROUP BY carrier
  The columns of df are listed under the input, narrowed to the name being
  typed. A long statement wraps onto up to four lines.
  For values that will not convert, TRY_CAST(col AS INT) reads them as
  null; trim text with SUBSTR or REPLACE before STRPTIME.
  Enter on a row of a GROUP BY result shows the rows of df behind it,
  after the WHERE; Esc comes back. Only for one table grouped by selected
  keys: no joins, subqueries, WITH, UNION or window functions.

Search:
  Every word's letters in order, in any text column. A row matches when,
  for each word, one of its text columns holds that word's letters in
  order, not necessarily adjacent, so "smth" finds "Smith". Matching is
  case-insensitive and needs at least one text column. Reopened after a
  search, the prompt shows how many rows matched.

q-style:
  A subset of the q language, datui's own: it evaluates right to left and
  is not a complete q or q-sql. The syntax follows; the user guide's
  Query syntax page is the full reference.

q-style Syntax:
  select [columns] [by group_cols] [where conditions]

Basic Examples:
  select a, b where a > 10, b < 5
  select a, b by category where a > 10
  select by city, state
  select avg[price], count[a] by category, region
  select a, b:"foo" where name="george", age > 7
  select col["first name"], col[last_name]:"derek"

Column Selection:
  - List columns: a, b, c
  - Use aliases: total:a + b
  - Empty select: select (selects all columns)
  - Distinct rows: select distinct carrier, origin
  - With grouping: select by city (all columns grouped by city)
  - String literals: b:"foo" (creates column b with value "foo")
  - Column names with spaces: col["first name"] (the quotes are required)
  - col[] syntax works for any column: col[name] or col["name"]

Column Assignment (by clause):
  - Create computed columns: by new_col:city+state
  - Use expressions: by area:width*height
  - Supports same operations as select clause

Aggregation Functions (square brackets optional):
  avg[expr] or avg expr    - Average value (also: mean)
  min[expr] or min expr    - Minimum value
  max[expr] or max expr    - Maximum value
  count[expr] or count expr - Count of non-null values
  std[expr] or std expr    - Standard deviation (also: stddev)
  med[expr] or med expr    - Median value (also: median)
  sum[expr] or sum expr    - Sum of values
  first[expr], last[expr]  - First and last value in the group
  nunique[expr]            - Count of distinct values
  var[expr], dev[expr]     - Variance, standard deviation (sample)
  w wavg x                 - Average of x weighted by w

  Unaliased aggregates of a column are named fn_column (avg[salary] ->
  avg_salary); an alias overrides this (total:sum[price] -> total).

Aggregation Examples:
  select avg[price], min[quantity], max[date] by category
  select avg price, min quantity, max date by category
  select total:sum[price*qty], count[id] by region
  select avg[price], std[price] by category, region

Functions (square brackets optional):
  not[expr]                - Logical negation (not a=b is a!=b)
  null[expr]               - True where the value is null
  len[expr] (length)       - String length in characters
  upper[expr], lower[expr] - Change a string's case
  abs[expr]                - Absolute value
  floor[expr], ceil[expr]  - Round down or up (ceil also: ceiling)
  sqrt[expr], log[expr], exp[expr] - Square root, natural log, e^x

Dates and strings:
  Date columns have dot-accessors (order_date.year, pickup.hour) and
  date literals are written YYYY.MM.DD; strings have their own accessors
  (city.contains["York"]). Accessors chain left to right.
    DATE.to_date["%Y%m%d"]      - Parse text (to_datetime for times)
    score.part["-", 0].int      - Split on -, piece 0, as a number
    s.slice[0, 3], s.replace["(P)", ""], s.strip
    x.round[1], x.int, x.float, x.str
    (avg delay).round[1]        - Parentheses to round an aggregate
  The Query syntax reference has the full list.

Grouping:
  - Group by columns: select a, b by category, region
  - Group with aliases: by region_name:region, total:sales+tax
  - Empty select with grouping: select by city, state
  - All non-group columns collected as lists
  - Enter on a result row drills into its rows, aggregated or not;
    Esc comes back

Where Conditions:
  - Multiple conditions: a > 10, b < 5 (AND)
  - OR within condition: a > 10 | a < 5
  - , and | are logic only inside where; elsewhere , separates columns
  - Expressions: 100 < (a + b) * 2
  - String comparisons: name="george", city="New York"
  - Use not function: not[a=b]
  - Note: Where clause does NOT support column assignment

Operators:
  Math:        +, -, *, / or % (both divide)
  Comparison:  =, !=, <>, <, >, <=, >=
  Logic:       , (AND), | (OR)
  Coalesce:    ^ (a^b is the first non-null of a, b)
  Remainder:   x mod 7
  Membership:  name in ["Emma", "Olivia"]
  Pattern:     item like "*Chicken*" (* any text, ? one character)
  Buckets:     5 xbar fare (fare rounded down to a multiple of 5)

Expression Evaluation:
  - Operators evaluated right-to-left
  - Example: 1/c+a evaluates as 1/(c+a)
  - The trap: (a+b)*2 > 100 parses as (a+b) * (2 > 100), not a comparison
    of the product. Put the comparison first: 100 < (a+b)*2
  - Use parentheses () for grouping: (a+b)*2
  - Square brackets [] are for function calls only

Function Syntax:
  - Aggregation: avg[expr], sum[expr], etc.
  - Logic: not[expr]
  - Brackets optional: avg 5+a (same as avg[5+a])
  - Brackets optional: not a=b (same as not[a=b])
  - Use parentheses for grouping: (a+b)*2
  - Example: b:avg[(1%c)+a] or b:avg (1%c)+a
