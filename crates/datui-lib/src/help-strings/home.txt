The home screen is where datui starts when you launch it without a path, and
where Ctrl+O returns you from anywhere.

NAVIGATION
  ↑ / ↓             Move the selection (Ctrl+P / Ctrl+N as well)
  Ctrl+↑ / Ctrl+↓   Previous or next section
  ← / →             Collapse or expand a section; the choice is remembered.
                    → on any folder goes inside it instead, whatever its label,
                    so one partition or one file can always be reached
  PgUp / PgDn       Move ten rows

  Every letter types into the filter, so none is a key here: "json" finds json.
  Tab               Cycle the sort. The control bar names the order in effect
                    where the cursor is: "recent" under Recent, "name" under a
                    directory, or size / modified / rows once chosen.
  Enter             Open the dataset, enter the directory, source or bucket, or
                    fold the section. A hive folder, or one whose files hold the
                    same table, opens as one dataset; one labelled delta, iceberg
                    or hudi is a lake table datui does not read yet, and Enter
                    goes inside it
  Backspace         Leave a directory you descended into; from a bucket, back
                    to its cloud source
  Ctrl+R            List again what is on screen: every cloud source, the one
                    you are in, or the bucket or directory
  Esc               Back out one layer: the filter, the directory, then the data
  Ctrl+C            Quit

  Inside a folder with anything in it, the first row is "<folder> (all files)",
  or "(all partitions)" for a hive folder. Enter on it opens the whole folder
  whatever the folder is labelled, so a label that is wrong costs a keystroke
  rather than access. It carries no label itself, and it steps out of the way
  while a filter is typed. What can be read through it is narrower than what it
  opens: on disk a folder of more than one kind of data file says so, in a bucket
  only Parquet is read in place and a prefix whose own files are not Parquet
  names what it holds, and a lake table says why on both.

  A folder's label says what is directly inside it: hive, delta, iceberg, hudi,
  a count and a format ("12 parquet"), "mixed" for more than one format, or
  "dir" for no data files — in a bucket, the word for the place instead. The
  details pane carries the whole tally: every file in the folder is counted, as
  data, as one datui has no reader for, or as one it passed over. Passed over is
  a name ending "_$folder$", which some tools write to stand in for a folder, or
  beginning "_" or "." — where every engine puts its own files and a repository
  puts .git. Otherwise a "key=value" name is a partition whatever it begins
  with. The skipped are named, the first four of them.

FINDING
  (type)            Filter by name or column; matching is fuzzy, so "sal" finds
                    "sales", and "customer_id" finds every dataset with that column
                    Typing also searches below the working directory, and the
                    bucket names already listed; matches appear under "Found"
  Backspace         Delete a filter character
  ~                 Type a path directly, for somewhere datui has not seen yet
  Tab               (while typing a path) complete it
  Delete            Forget the highlighted entry under Recent, or hide a cloud
                    source (--clear-cache shows it again)
  Shift+Delete      Forget every recent entry, after confirming
  Ctrl+U            Clear the filter or path input

WHERE THESE COME FROM, IN ORDER
  Recent            Datasets you have opened before, most recent first
  Current directory Where you launched datui
  Cloud             One row per cloud source. Enter lists its buckets
  Configured        Directories from [data] directories, in the order listed
  Recent dirs       Directories of datasets you have opened, 8 most recent.
                    Start folded.
  Elsewhere         Directories your desktop recorded, listed unexpanded.
                    Starts folded.
  Found             Datasets under the working directory, from the search that
                    typing starts. Shown only while you are typing.

  Filtering keeps this grouping, so a match shows which root it came from.

  Opening a dataset also teaches datui about the directory holding it, so a
  dataset on a mount only has to be found by hand once.

  A folder labelled … has not been looked into yet. Finding out what a folder
  is costs a directory read, so no listing pays for it: the rows are drawn at
  once and labelled a screenful at a time as you scroll, highlighted row first.
  Nothing moves when a label arrives.

  datui stores nothing about your data except this list of recent paths.
