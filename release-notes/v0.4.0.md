## What's changed

### The interface overhaul

The whole surface was rebuilt on one component kit over #313-#320: one border per dialog, keys as chips in a footer instead of buttons, one accent for focus, type-to-narrow pickers instead of arrow-cycled lists, and every screen legible in plain ASCII terminals. Enter applies and Esc discards, everywhere. The entries below carry the details per screen.

- A finished export says so in one line on the bottom bar, gone on the next key; nothing to dismiss (#336)
- Error and confirmation dialogs match the rest of the UI: the message and the keys, no buttons (#336)
- Enter on an incomplete pivot or melt highlights what is missing in the form instead of raising an error (#336)
- The bottom bar's count reads `1,000 rows`, abbreviating large totals like the home screen (`417,321 of 1.2M`); a pivoted or melted view carries a chip saying so, and `R` takes it away (#336)
- Ctrl+W and Ctrl+U edit a picker's search text; chords no longer type their letters there or in the view save form (#336)
- Ctrl+U in a text field deletes to the start of the line, as in a shell, and undo moves to Ctrl+Z; Ctrl+J saves or applies wherever Ctrl+Enter does, on every terminal, instead of deleting text (#371)
- Typing into a field the form filled in, such as a new view's name or melt's `variable` and `value`, replaces the default instead of appending to it; an arrow key keeps it for editing (#451)
- End jumps to the bottom of a help screen (#337)


### Home screen

- Run `datui` with no path: recent datasets, the current directory, your data directories and cloud sources, with rows, columns and size before you open anything (#145, #280, #285)
- Type to filter by name or column name; Ctrl+O returns here from anywhere
- Directory labels say what is inside (`12 parquet`, `mixed`, `delta`) (#243, #272, #278)
- → goes inside any directory; its `(all files)` row opens the whole directory as one table (#279, #286)
- Ctrl+D keeps a directory listed on the home screen without editing the config; press it again to forget
- `datui <directory>` opens a directory with no `--hive` flag (#286, #288)
- Files datui cannot read are hidden; Ctrl+A shows them, dimmed (#296)

### Directories of files

- A directory opens as one table when its files' columns fit the widest file's, for Parquet, CSV and NDJSON (#234, #284, #287)
- Files that disagree are read as the union of their columns, and the Info panel's Notes tab says what was found (#197, #204, #209)
- Delta, Iceberg and Hudi tables are labelled, not read as plain Parquet (#243)
- Exports can add a column naming each row's source file (#205)

### Cloud

- The public catalog now links to flights, food, names, weather, football, taxis, earthquakes, launches and penguins alongside blockchain data and Overture Maps; HTTP(S) files open directly, no data is bundled, and saved catalog configurations are preserved
- A CLOUD section with one row per store: S3 and S3-compatible servers, AWS profiles, Google Cloud, Azure Blob Storage, MinIO and s3cmd, found from the logins you already have (#181, #182, #183, #185, #187, #188)
- `[[sources]]` names collections of datasets, local files and directories beside S3, Google Cloud, Azure and HTTPS URLs, each listed under its label on the home screen; a dataset can be read anonymously or through a named connection (#358)
- `[[cloud.connections]]` adds stores, with secrets kept in the environment or a password manager, never the config (#181, #189)
- Built-in public datasets open with no login, as a collection you can replace, turn off with `[data] builtin_catalog = false`, or hide with `[data] hide_sources` (#186, #203, #358)
- Sources are listed when you enter them; `[cloud] discover` chooses which logins become sources (#293)
- `datui gs://bucket/dir/` reads a directory of CSV or JSON Lines in place, and `~` takes cloud URLs (#296)
- Remote Parquet reads one row group at a time, and many-file datasets read only the files a page needs (#163, #191, #218)
- A single S3, Google Cloud or Azure file that has to be downloaded streams to disk instead of being held in memory whole, and Ctrl+O during any download, HTTP included, stops it and removes the partial file (#457)

### Data quality

- Data Quality reports what is wrong with a dataset in plain words: problems ranked above notes, missing values said once with each column's rate, the clean columns named with the checks they passed, and every finding's rows one Enter away, a sample's included; it reads the same sample as every other analysis tool, and profiles run by file, partition, row chunk or time window (#244, #269)
- Data Quality opens on one Setup with every setting a run takes (sample, time roles, grain, comparison) and reads nothing until Enter runs it; the run names each stage as it goes, and a cancelled read says it is still finishing rather than letting another start beside it (#415)
- Data Quality reads less: a sampled run counts its daily or partition segments in the pass that samples, and edits to roles, text formats, row chunks or a coarser window reuse the rows already read, and a new comparison reads nothing even after a full scan; Setup says before Run what will be read, and `d` there releases the kept rows (#415)
- A Data Quality full scan of a remote dataset that fits `quality_local_copy_mb` (2 GiB by default) and the free disk fetches each object once into the cache directory, and its passes and later full scans read that copy instead of the bucket; Setup says before Run whether it will, and `d` releases the copy (#415)
- Every Data Quality report says under its verdict how far it reaches: which checks ran on every row, a sample or file footers, which could not run and why, and the rows its reads went through; Esc stops a full scan within a batch (#415)
- Times stored as text, such as `01/31/2024 08:15:00`, can be read through a chosen format for time windows and intervals; values the format cannot read are reported as unparsed, not as missing (#415)
- Data Quality has an Intervals page: the time between any two time roles you choose, per segment, with missing ends, unread text, negative durations and threshold breaches each beside its denominator, and the rows behind a count one Enter away; text times with an offset, such as `2024-01-31T08:15:00Z`, read as UTC (#415)
- Duplicate rows open as the copies themselves, grouped, and Numbers as text opens the values that do not parse, each from the rows the run kept; rows a run did not keep are read only after a dialog says what the read is (#415)
- `c` and `t` narrow Data Quality's findings to one column or one type, and `o` orders them by rows affected or by rate, without reading anything again (#415)
- A Data Quality trend bar opens to what it spans, the rows sampled of the rows counted, its rate with a 95% interval, and the change from the bar before; days a sample missed are marked rather than dropped, and `w` stages a coarser window in Setup (#415)
- Setup can say which time windows rows are expected in, such as weekdays through 2024; Trends then lists the windows with no rows, told apart as empty, not sampled or outside the scope, and stating them reads nothing (#415)
- Declare what columns must hold in Data Quality Setup: a key, required fields, allowed values, a range, or text read as a number; violations are counted as problems with their rows, from the rows the run already reads (#415)
- `x` exports a Data Quality report as versioned JSON or a short Markdown report, with the setup, source and reads behind it, without reading the data again (#415)

### Analysis on large tables

- Describe, Distribution and Correlation analyze a 100,000-row sample of a larger table, spread across all of it: a few dozen row groups of one Parquet file, or one streamed pass over anything else that holds only the sample. 37 million rows of NOAA weather data in S3 take seconds
- One sample serves every analysis tool, Data Quality included: `s` chooses the rows (a partition, a list or range of them, files, a time range), the method (random, equal per value, first rows, every row), the size and the seed; the first run on a dataset starts from the form and later tools reuse its sample, and `v` shows the sample's rows in the table viewer
- The title says what was read (`sample of 100,000 of 36,839,175 rows`); `r` draws another sample and `a` reads every row
- Describe gives date, datetime, time and duration columns their range, quartiles and mean, written as the table writes them (#383)
- Esc cancels a run in progress, and the progress shows elapsed time instead of a bar that could not move
- The Q-Q plot rises with the data instead of folding over at the median, the normality p-value beside it is a real one, and the histogram's bars line up with its axis
- Distribution p-values are calibrated: each family is fitted once, tested by Kolmogorov-Smirnov against 199 samples drawn from the fit and refitted, and drawn in the Q-Q plot and histogram with the same parameters; a family that cannot describe a column says why instead of ranking a placeholder score
- Distribution fitting names a column only when a distribution fits it: `Constant` for one value, `No clear fit` when every candidate is rejected, and the simpler family when two fit alike
- `[performance] analysis_sample_rows` (and `--sample-rows`) replaces `sampling_threshold`, which is no longer read; 0 reads every row
- Charts sample the same way instead of reading the table's first rows, and say so under the plot and in an exported PNG or EPS (`sample of 10,000 of 3.5M rows`); the chart's Limit rows is now Sample size (#364)
- Histogram, Box Plot and KDE take a Range option, p1-p99, that leaves out values beyond the 1st and 99th percentiles and counts them under the plot (#364)

### Copy to the clipboard

- `y` copies from the table: the current cell, the current row, the rows on screen, or the whole view as queried, filtered and sorted (#310)
- Formats: TSV (what a spreadsheet expects from a paste), CSV, or an aligned Markdown table; TSV and CSV copies through the display server also carry an HTML table flavor, so a paste into a spreadsheet or an email keeps its columns (#310)
- Works locally through the display server and over SSH through OSC 52; `[clipboard] backend` chooses, `auto` picks for you (#310)

### Fixed

- An export, chart or Data Quality report that fails part way leaves the file it was replacing untouched instead of truncated, and an error writing a compressed file's end is reported instead of lost (#454)
- A setting in your config wins over an import even when it equals the default, so `notes_accent = true` undoes an imported `false` and a color written as its default value takes effect (#456)
- A config file that cannot be read or parsed stops datui with its path, line and reason, instead of starting on the defaults and dropping every setting in it (#456)
- `datui --generate-config` lists the settings that are unset by default, such as `[theme] mode`, `[file_loading]` options, `sidebar_width` and `log_file`, with example values that parse (#456)
- CSV export of a list or struct column, such as a `by` result or SQL `ARRAY_AGG`, writes the cells as JSON instead of failing; clipboard copies do the same (#411)

- CSV export of a duration column, such as the difference of two datetimes, writes ISO 8601 text like `PT3723.004S`, as JSON export does, instead of failing; TSV and CSV copies do the same (#482)

### Rust library

- `DataTableState`'s pipeline fields are private (#458). Read them with `lf()`, `schema()`, `num_rows()`, `error()`, `start_row()`, `partition_columns()`, `polars_streaming()`, `drilled_group_key()` and the `get_active_*query()` methods; `into_lf()` takes the frame and `dismiss_error()` clears the message
- `defer_collect` is gone: `deferred(|s| ...)` runs steps without collecting, and `try_transition(|s| ...)` plans them as one step that rolls back on error and returns the `ViewRollback` checkpoint (#458)
- `set_num_rows` is replaced by `count_landed(len_generation, rows, file_row_groups)`, which takes a count only for the frame on screen; `ViewRollback::count_landed` keeps one for the view a checkpoint restores (#458)
- `InfoContext` takes `facts: Option<&FileFacts>` and `parquet_file: bool` in place of `path` and `parquet_metadata`; `file_size_bytes()` is gone, `parquet_metadata()` reads the footer from the facts, and `FileFacts::read` does the blocking read for a worker (#457)
- `export::write` is replaced by `export::run(lf, request, polars_streaming, written)`, which plans, writes and commits an export, streaming uncompressed CSV and Parquet; `ExportRequest::route` says which way it goes. `DataTableState::export_frame(name_files)` replaces `name_source_files` and `drop_row_index`. `AppEvent::DoExportCollect`, `DoExportWrite` and `BackgroundExportCollected` are gone, `BackgroundExportWriting` reports bytes written, and `LoadingState::Exporting` carries `written` instead of `progress_percent` (#454)
