## What's changed

### The interface overhaul

The whole surface was rebuilt on one component kit over #313-#320: one border per dialog, keys as chips in a footer instead of buttons, one accent for focus, type-to-narrow pickers instead of arrow-cycled lists, and every screen legible in plain ASCII terminals. Enter applies and Esc discards, everywhere. The entries below carry the details per screen.

- `/` is Find and `:` the command line: digits go to a row, anything else runs as SQL or q (Ctrl+T switches, and the choice is remembered)
- Find lights up its matches on screen as you type; Ctrl+G keeps only the matching rows as a filter, and Ctrl+T matches letters in order (`chkn` finds `Chick-n-Strips`), which replaces the Text query mode
- `[` and `]` sort by the cursor's column, ascending or descending, and the same key again takes the sort away; Shift+← → page the columns
- A status footer replaces the control bar: the dataset, query, filters and sort on one line with the row position, the keys of the mode in effect, and `? keys` for the rest; it grows for a prompt or a find's progress
- The mouse reaches dialogs and the table: a click focuses a field and acts on it, switches a tab, or presses what the footer shows (the filters open the sidebar, `query` the command line); dragging a header moves its column, dragging its edge sets its width, and a right click on a cell opens a menu of its keys
- A finished export says so in one line in the footer, gone on the next key; nothing to dismiss (#336)
- Error and confirmation dialogs match the rest of the UI: the message and the keys, no buttons (#336)
- Enter on an incomplete pivot or melt highlights what is missing in the form instead of raising an error (#336)
- A pivoted or melted view says so in the footer, and `R` takes it away (#336)
- Ctrl+W and Ctrl+U edit the text that narrows a picker; chords no longer type their letters there or in the view save form (#336)
- Ctrl+U in a text field deletes to the start of the line, as in a shell, and undo moves to Ctrl+Z; Ctrl+J saves or applies wherever Ctrl+Enter does, on every terminal, instead of deleting text (#371)
- Every dialog takes the same keys: ↑ ↓ and Tab move between fields from the moment it opens, ← → change a choice, Space acts on the field, Enter applies from anywhere, and Ctrl+P / Ctrl+N recall a text field's history
- Pivot & Melt opens full screen beside a live preview of the result, its first rows typed like the table and its shape, updated as you change the form; a pivot that would make more than 10,000 columns is refused with the count
- Sort & Filter opens on what is in effect: each sort and filter is a row to flip, edit, reorder or remove, with a row to add one; the columns list is its second tab
- `?` shows each screen's keys grouped by task, in two columns: `/` narrows them as you type, and Enter on one closes the help and runs it
- Typing into a field the form filled in, such as a new view's name or melt's `variable` and `value`, replaces the default instead of appending to it; an arrow key keeps it for editing (#451)
- End jumps to the bottom of a help screen (#337)


### Loading

- Text files open at once, whatever their size: the first rows show while the rest of the file is indexed behind them
- Pipes show rows as they arrive: `cmd | datui` reads on to the end of the stream with the view where you put it, `journalctl -o json | datui` included
- Datasets of many files show an estimated row count at once, `~4.12B (est.)`; the exact count follows with its progress in the footer, Esc stops it, and past 50,000 files `c` on the Info panel asks for it
- `#` numbers rows by their place in the source and keeps the number through a sort or filter; on for text and logs, which no longer have a `line_no` column
- A CSV padded with NUL bytes after its last line, as some loggers preallocate them, ends at its text, and a byte that is not UTF-8 reads as `�` instead of failing the read
- Typing text columns keeps codes with leading zeros (`02134`) as text, and the Notes tab counts the values past the sample that did not parse

### Home screen

- Run `datui` with no path: recent datasets, the current directory, your data directories and cloud sources, with rows, columns and size before you open one (#145, #280, #285)
- Type to narrow by name or column name; Ctrl+O returns here from anywhere
- Each home section's rule carries its count (#547)
- The search below the current directory finds a match however many other files it walks past, says when it stopped short with nothing found, and keeps up with typing in trees of tens of thousands of files (#547)
- Directory labels say what is inside (`12 parquet`, `mixed`, `delta`, `3 dirs`), and every row reads `name/  label` alike (#243, #272, #278, #547)
- → goes inside any directory; its first row opens the whole directory as one table and says how (`hive table: year, month`, `3 Parquet files, one schema`, `all files, mixed`), and the cursor starts there only when that is one dataset (#279, #286, #547)
- Catalogs: a TOML file of named datasets and directories, local or remote, is a section of the home screen. `catalog.toml` is yours, and Ctrl+D on any row adds it there, keeping your comments and layout; Ctrl+D again forgets it. Files in `catalogs/` beside it, or listed with `catalogs = [...]`, add a team's, and `datui catalog show` and `datui catalog check FILE` print and check them, a mistake named by its line
- Ctrl+E on a catalog row shows its documentation full screen: publisher, license, links whole (`y` copies one, `o` opens an http or https one in the browser after showing the whole URL), columns with units and value legends, and bookmarks; Info's Documentation tab shows the same page for the open dataset
- `datui <directory>` opens a directory with no `--hive` flag (#286, #288)
- Files datui cannot read are hidden; Ctrl+A shows them, dimmed (#296)
- A file a format spec knows by its magic, such as `data.bin`, is listed under the spec's name, with the spec, what matched and the spec's columns or record types in its details; search finds it too, and `datui formats` and the Notes tab show each match the same way (`magic MKTD · version 1`)
- Selecting a local CSV, Parquet, JSON Lines or Arrow file shows its first rows on the home screen, and Enter opens the file on those rows without reading them again (#547)
- Recent is ranked by how often and how lately you open each dataset, and typing ranks what you open most first; Enter at launch still reopens the last file (#547)
- At `~`, the list shows the directory being typed: Tab completes, the arrows pick, and `s3://noaa` + Tab completes the bucket from what datui already knows (#547)
- Public dataset rows show their format and size, a file under 50 MB opens without a download question, and an opened one comes back under Recent by its name and shape (#547); one that turns out larger stops at 50 MB and asks once
- The last column on screen runs to the right edge, so a long text column on the far right shows more of each value
- A file row that is not read lazily says so (`converts`, `in memory`, `downloads`), and the docs list how each format is read (#638)
- A CSV opened with `--footer-rows` says `Counting rows to skip the footer` while it counts the file before the first row (#682)
- Opening a file read whole into memory, such as a large JSON, asks first past 1 GB: `big.json: JSON reads 2.10 GB into memory`; `[read] memory_warning` sets the size, 0 never asks (#682)

### Directories of files

- A directory opens as one table when its files' columns fit the widest file's, for Parquet, CSV and NDJSON (#234, #284, #287)
- Files that disagree are read as the union of their columns, and the Info panel's Notes tab says what was found (#197, #204, #209)
- A file with no header, empty or only NUL bytes, is skipped with a note instead of stopping the read
- Delta, Iceberg and Hudi tables are labelled, not read as plain Parquet (#243)
- Exports can add a column naming each row's source file (#205)
- A local Parquet directory of more than 64 files opens from its first and last files while the rest are read in the background, counts its rows from those same footers, and reopens without reading any if nothing changed; on a network mount, rows show in a fraction of the time (#643)

### Cloud

- The public catalog now links to flights, food, names, weather, football, taxis, earthquakes, launches and penguins alongside blockchain data and Overture Maps; HTTP(S) files open directly, no data is bundled, and saved catalog configurations are preserved
- A CLOUD section with one row per store: S3 and S3-compatible servers, AWS profiles, Google Cloud, Azure Blob Storage, MinIO and s3cmd, found from the logins you already have (#181, #182, #183, #185, #187, #188)
- A catalog lists local files and directories beside S3, Google Cloud, Azure and HTTPS URLs; a dataset can be read anonymously or through a named connection (#358)
- `[[cloud.connections]]` adds stores, with secrets kept in the environment or a password manager, never the config (#181, #189)
- Public datasets open with no login, from a bundled catalog you can print (`datui catalog show public`), replace with your own `public.toml`, or hide with `[home] hide` (#186, #203, #358)
- A catalog's dataset can carry documentation: what its columns mean and what their codes stand for, shown on the home screen, in Info and in the inspector, plus bookmarks to start from; NOAA weather, NYC taxis, flights and earthquakes ship with their publishers' notes (#734)
- A web file's row shows the catalog's `~33 MB` until a HEAD, sent when the row is selected, measures it
- Sources are listed when you enter them; `[cloud] discover` chooses which logins become sources (#293)
- `datui gs://bucket/dir/` reads a directory of CSV or JSON Lines in place, and `~` takes cloud URLs (#296)
- Remote Parquet reads one row group at a time, and many-file datasets read only the files a page needs (#163, #191, #218)
- A large S3 or Google Cloud prefix lists in parallel and counts the files as it goes: NOAA's 842,000-file `by_station` lists in 8 seconds instead of 90, and its row count reads each footer once and is remembered, so a reopen reads none (#690)
- A huge bucket prefix on the home screen shows its first rows within a page's latency and stops at 5,000 with `first 5,000`; typing asks the bucket for the names past that, and leaving stops the listing. NOAA's 141,000-station `by_station` level lists in under a second instead of 12 (#711)
- A local Parquet directory of more than 20,000 files reads each footer once, counts its listing on the loading screen (Ctrl+O stops it), and reopens without reading any footers; its partition columns match the same tree read from S3 (#710)
- A single S3, Google Cloud or Azure file that has to be downloaded streams to disk instead of being held in memory whole, and Ctrl+O during any download, HTTP included, stops it and removes the partial file; so does quitting, or closing the terminal, mid-download or mid-decompression (#457, #510)

### Data quality

- Data Quality reports what is wrong with a dataset in plain words: problems ranked above notes, missing values said once with each column's rate, the clean columns named with the checks they passed, and every finding's rows one Enter away, a sample's included; it reads the same sample as every other analysis tool, and profiles run by file, partition, row chunk or time window (#244, #269)
- Data Quality opens on one Setup with every setting a run takes (sample, time roles, grain, comparison) and reads nothing until Enter runs it; the run names each stage as it goes, and a cancelled read says it is still finishing rather than letting another start beside it (#415)
- Data Quality reads less: a sampled run counts its daily or partition segments in the pass that samples, and edits to roles, text formats, row chunks or a coarser window reuse the rows already read, and a new comparison reads nothing even after a full scan; Setup says before Run what will be read, and `d` there releases the kept rows (#415)
- A Data Quality full scan of a remote dataset that fits `[analysis] quality_local_copy` (2GiB by default) and the free disk fetches each object once into the cache directory, and its passes and later full scans read that copy instead of the bucket; Setup says before Run whether it will, and `d` releases the copy (#415)
- Every Data Quality report says under its verdict how far it reaches: which checks ran on every row, a sample or file footers, which could not run and why, and the rows its reads went through; Esc stops a full scan within a batch (#415)
- Times stored as text, such as `01/31/2024 08:15:00`, can be read through a chosen format for time windows and intervals; values the format cannot read are reported as unparsed, not as missing (#415)
- Data Quality has an Intervals page: the time between any two time roles you choose, per segment, with missing ends, unread text, negative durations and threshold breaches each beside its denominator, and the rows behind a count one Enter away; text times with an offset, such as `2024-01-31T08:15:00Z`, read as UTC (#415)
- Duplicate rows open as the copies themselves, grouped, and Numbers as text opens the values that do not parse, each from the rows the run kept; rows a run did not keep are read only after a dialog says what the read is (#415)
- `c` and `t` narrow Data Quality's findings to one column or one type, and `o` orders them by rows affected or by rate, without reading anything again (#415)
- A Data Quality trend bar opens to what it spans, the rows sampled of the rows counted, its rate with a 95% interval, and the change from the bar before; days a sample missed are marked rather than dropped, and `w` stages a coarser window in Setup (#415)
- Setup can say which time windows rows are expected in, such as weekdays through 2024; Trends then lists the windows with no rows, told apart as empty, not sampled or outside the scope, and stating them reads nothing (#415)
- Declare what columns must hold in Data Quality Setup: a key, required fields, allowed values, a range, or text read as a number; violations are counted as problems with their rows, from the rows the run already reads (#415)
- `x` exports a Data Quality report as versioned JSON or a short Markdown report, with the setup, source and reads behind it, without reading the data again (#415)

### Analysis on large tables

- Describe, Distribution and Correlation analyze a 100,000-row sample of a larger table, spread across all of it: a few dozen row groups of one Parquet file, or one streamed pass over anything else that holds only the sample. 37 million rows of NOAA weather data in S3 take seconds
- One sample serves every analysis tool, Data Quality included: `s` chooses the rows (a partition, a list or range of them, files, a time range), the method (random, equal per value, first rows, every row), the size and the seed; the first run on a dataset starts from the form and later tools reuse its sample, and `v` shows the sample's rows in the table viewer
- The title says what was read (`sample of 100,000 of 36,839,175 rows`); `r` draws another sample and `a` reads every row
- Describe gives date, datetime, time and duration columns their range, quartiles and mean, written as the table writes them (#383)
- Esc cancels a run in progress, and the progress shows elapsed time instead of a bar that could not move
- The Q-Q plot rises with the data instead of folding over at the median, the normality p-value beside it is a real one, and the histogram's bars line up with its axis
- Distribution p-values are calibrated: each family is fitted once, tested by Kolmogorov-Smirnov against 199 samples drawn from the fit and refitted, and drawn in the Q-Q plot and histogram with the same parameters; a family that cannot describe a column says why instead of ranking a placeholder score
- Distribution fitting names a column only when a distribution fits it: `Constant` for one value, `No clear fit` when every candidate is rejected, and the simpler family when two fit alike
- The correlation matrix switches between Pearson and Spearman with `m`, shows three decimal places (four for the selected pair), and never rounds a near-perfect correlation up to 1.000
- `[analysis] sample_rows` (and `--sample-rows`) replaces `sampling_threshold`; 0 reads every row
- Charts sample the same way instead of reading the table's first rows, and say so in the chart's title row and in an exported chart (`sample of 10,000 of 3.5M rows`); the chart's Limit rows is now Sample size (#364)
- Histogram, Box Plot and KDE take a Range option, p1-p99, that leaves out values beyond the 1st and 99th percentiles and counts them under the plot (#364)

### Column cursor

- Key change: `h`/`l` and ←/→ move a column cursor instead of scrolling the view a column; the view scrolls only when the cursor would leave the screen, frozen columns included, and `[` `]` `{` `}` and `g` move the cursor too (#574)
- The cursor's column is tinted from header to last row, the cell where it crosses the current row stands out from both, and the footer says where it is (`col 43/300`); the `column_cursor` and `cell_cursor` theme slots set the tints (#574)
- `F`, a Cell copy, the Sort & Filter sidebar, the inspector and a find limited to one column act on the cursor's column, a find's match moves the cursor to its column, and the cursor stays on its column when columns are hidden, moved or frozen (#574)
- `<` `>` make the cursor's column narrower or wider as you type, `=` fits it to the rows on screen and `w` gives it back its automatic width, without opening Sort & Filter (#647)
- `+` keeps the rows with the cursor's cell's value and `-` drops them, each a filter added to Sort & Filter's list that `R` clears (#737)
- `H` and `L` move the cursor's column one place left or right (#737)

### Value counts

- `F` counts the column cursor's values: each value's rows, percent, cumulative percent and a bar, nulls on a line of their own, under a summary of rows, distinct values and nulls, and for numbers the sum, mean, min and max (#558)
- Enter shows the rows holding a value as a drill-down and Esc comes back to the counts; `s` sorts by value, `y` and `e` copy and export the counts (#558)
- A remote or very large Parquet file is counted from a sample first, and says so; `a` counts every row (#558)
- Key change: `,` toggles digit grouping, which was `F` (#558)
- A number column opens as its histogram, binned from the counts; `c` turns to the listing and back

### Binary files

- Fixed-record binary files open as tables from a TOML spec found on a search path (`~/.config/datui/formats`, `$DATUI_FORMATS_PATH`, `[formats] path`), matched by glob or magic, or named with `--format NAME` or `--format ./FILE.toml`; `datui formats` lists the specs and `datui formats check` validates one in CI (#578)
- Format specs also read length-prefixed and sync-marked records, message types picked by a type field (one table, or one type alone with `--table` or from its row inside the file on the home screen), footers with a count or checksum, and blocks compressed one at a time (#578)
- A full query over a format spec's variable-length records reads every column from one walk of the file, about four times faster, and a file opened again with the same spec is not walked again (#662)
- `--format` takes a spec's http(s), S3, Google Cloud or Azure URL as well as a file (#662)
- `datui formats check` checks DBC dictionaries too, by name or file, and given a candump log says how many frames it names (#727)
- A format spec can document its files as a catalog does: a description and a `documentation` link, a description for each record type, and a description and unit for each column, its `enum` read as the value legend; Ctrl+E on the home screen and Info's Documentation tab show them, under a catalog entry's own notes for the same file
- A spec of `kind = "delimited"` opens a family of instrument or logger CSV exports with no flags: its dialect, a units line shown beside each column's type, a metadata line in the Info panel, and a datetime built from date, time and UTC offset columns; a dialect flag typed on the command line still wins over the spec (#599, #651)
- A delimited spec can give a column of the file a `type`, the names the type row shows; a value that does not fit is null, and the Notes tab counts them. Files read together through a spec, a directory or a glob, stack by column name
- `contrib/formats/garmin-txi.toml` reads Garmin TXi data logs, every column typed and a UTC `time` built from the local date, time and offset
- A column's type can be changed in the table, from the Info panel's Schema tab or the cell menu, with the same names and formats as a spec's `type`, and the cell menu combines a date, a time and an offset into a datetime; a saved view keeps both
- A local file no reader or spec takes opens in a hex view with find, go to offset, a byte inspector and `--hex-width`; Ctrl+X on the home screen, `x` in the Info panel and `--hex` show any local file there (#588)

### Copy to the clipboard

- `y` copies from the table: the current cell, the current row, the rows on screen, or the whole view as queried, filtered and sorted (#310)
- Formats: TSV (what a spreadsheet expects from a paste), CSV, or an aligned Markdown table; TSV and CSV copies through the display server also carry an HTML table flavor, so a paste into a spreadsheet or an email keeps its columns (#310)
- Works locally through the display server and over SSH through OSC 52; `[clipboard] backend` chooses, `auto` picks for you (#310)
- The Python (Polars) scope copies the view as a Python script that rebuilds it: the file read with datui's reader options, then the query (q, SQL or Text), pivot or melt, drill-down, filters, sort and columns, in the order applied (#614)
- Copy as Python reads a SQLite table through `sqlite3` and a NumPy array through `np.load`, saying when it reads whole what datui read lazily, reads a file datui knew by its bytes as the format it read, and names the file and table where it leaves `df = ...` to fill in (#678)
- Copy as Python runs where the view ran: every object-store reader gets the S3 endpoint and region (a named source's own), an Azure account or `skip_signature` for a public bucket, `--tee` reads its file, and `--comment-char` becomes `comment_prefix` (#678)

### Command line and config

One option registry holds every config key, its flag and its Python keyword, so the three use one name, and the command line keeps the flags one run needs (#677).

- `-c KEY=VALUE` sets any config key for one run, repeatable: `datui -c csv.comment='#' data.csv`; a key's own flag still wins, and an unknown key names the nearest ones
- `datui config init`, `config path` (the files read, imports first) and `config keys` (every key, its value and what set it); `datui cache clear [--recents]`; `datui views list`, `rm NAME`, `clear`
- One flag per concept: `-t, --table` for any table in a file (an Excel worksheet and each record type of a format spec included), `-F, --format` for a built-in format, a spec's name or its file (`./acme.toml`), `--dict` for FIX and DBC dictionaries, `--infer-types[=COLS|off]` for typing string columns
- Named themes: `theme.dark` and `theme.light` pick one per mode, from the built-in `night-market` and `day-market` or a file in the config directory's `themes/`; `datui theme list` and `datui theme show NAME`
- `theme.mode = "auto"` asks the terminal for its background color, so a light terminal gets the light palette without `COLORFGBG`, and switches when the window regains focus after the scheme changed
- `--delimiter` takes `';'`, `tab`, `\t` or `0x1f`; `--null` replaces the config's list; optional values need `=`, so `--infer-types data.csv` keeps the path
- Sizes and durations carry their unit: `max_buffered = "512MiB"`, `follow_interval = "250ms"`
- A config key datui does not read is named on stderr with the nearest key, so a renamed one finds its new name
- `datui completions bash|zsh|fish|powershell|elvish` prints a shell completion script
- Manual pages for datui, each command, the config file (`man 5 datui-config`), the keys, the q syntax and the formats; packages and the release archives install them with the shell completions, and `datui man` shows them after `cargo install` (#705); without `man` installed (Windows), `datui man` prints the page as text
- Exit statuses are documented and fixed: 2 for a usage error, 130 when SIGINT ends the session, which now restores the terminal (#705)
- Python's `view()` and `DatuiOptions` take the same names (`datui.OPTION_NAMES`) and `config={...}` for any key; `view(x, format=...)` works

### Installing

- The Linux builds run on glibc 2.28 and newer (Debian 10, Ubuntu 20.04, RHEL 8 and later) and need no library beyond it; before a release is published, each one is run on Ubuntu 20.04 and 22.04, Debian 11 and 12, Rocky 8 and 9 and Amazon Linux 2023
- Linux arm64 on PyPI, beside the `.deb`, `.rpm` and archive
- `cargo binstall datui` installs the release archive; they are named by target triple, `datui-v0.4.0-x86_64-unknown-linux-gnu.tar.gz` and `datui-v0.4.0-x86_64-pc-windows-msvc.zip`
- The install script stops with the reason on a download or checksum it cannot verify, on musl or an older glibc, says what it adds to apt and asks first, runs what it installed before reporting success, and takes `--help`, `--user`, `-y` and `--no-verify`

- Ctrl+C no longer quits — and `?` no longer opens help — while typing a Data Quality scope; the scope input is an ordinary text field
- A letter with Ctrl or Alt held no longer triggers table features: Ctrl+E opened Export, Ctrl+R reversed the sort, and so on
- A view saved on an S3, Google Cloud, Azure or HTTP dataset matches that URL again, and a view whose query renames columns still matches the next file by schema (#381)
- A view saved after a pivot or melt keeps the query, filters and sort it ran over and replays them first, and replays SQL run on the pivot after it (#412)
- Esc from a drill-down shows the grouped rows again, with the cursor on the group and its key column frozen; the group's rows used to stay on screen (#380)
- Columns keep their widths while you page, scroll or open a sidebar, and Sort & Filter's Columns tab makes a column narrower, wider or fitted to the rows on screen (#462)
- Space inspects the current row: every field, hidden ones included, whole and exact, with `y` to copy one; copies write floats as stored, not as the table rounds them (#462)
- Enter inspects the row too, wherever there is no group to drill down into (#542, #548)
- Shift+← → page a wide table's columns, `{` `}` go to the first column and the last page, `g` goes to a column by name, and the footer names the cursor's column, such as `col 43/300` (#462)
- A column name wider than the window no longer blanks the table, CJK and other wide text is measured in terminal cells, and a value or name cut short ends in `…`; frozen columns that do not fit beside the others scroll after a dashed separator instead of vanishing (#462)
- Describe and Distribution scroll to their last statistic and count the ones out of view, and the correlation matrix scrolls to keep the selected cell on screen (#369)
- `r`, a column order applied from Sort & Filter, and reading a column as text from the Notes tab read their rows in the background instead of freezing the screen (#458)
- The Info panel reads the file size and Parquet footer in the background, so opening it on an unresponsive share no longer freezes the screen; a file it cannot read says why in the panel (#457)

### Rust library

- `DataTableState`'s pipeline fields are private (#458). Read them with `lf()`, `schema()`, `num_rows()`, `error()`, `start_row()`, `partition_columns()`, `polars_streaming()`, `drilled_group_key()` and the `get_active_*query()` methods; `into_lf()` takes the frame and `dismiss_error()` clears the message
- `defer_collect` is gone: `deferred(|s| ...)` runs steps without collecting, and `try_transition(|s| ...)` plans them as one step that rolls back on error and returns the `ViewRollback` checkpoint (#458)
- `set_num_rows` is replaced by `count_landed(len_generation, rows, file_row_groups)`, which takes a count only for the frame on screen; `ViewRollback::count_landed` keeps one for the view a checkpoint restores (#458)
- `InfoContext` takes `facts: Option<&FileFacts>` and `parquet_file: bool` in place of `path` and `parquet_metadata`; `file_size_bytes()` is gone, `parquet_metadata()` reads the footer from the facts, and `FileFacts::read` does the blocking read for a worker (#457)
- `export::write` is replaced by `export::run(lf, request, polars_streaming, written)`, which plans, writes and commits an export, streaming uncompressed CSV and Parquet; `ExportRequest::route` says which way it goes. `DataTableState::export_frame(name_files)` replaces `name_source_files` and `drop_row_index`. `AppEvent::DoExportCollect`, `DoExportWrite` and `BackgroundExportCollected` are gone, `BackgroundExportWriting` reports bytes written, and `LoadingState::Exporting` carries `written` instead of `progress_percent` (#454)
- Background work has one owner, `jobs::Jobs` (#455). `AppEvent::JobEnded(Ticket)` replaces every background answer event (`BackgroundSchemaReady`, `BackgroundCollectReady`, `PivotReady` and the rest), `BackgroundFailed` and `BackgroundWorkFinished`; `AppEvent::JobProgress { ticket, progress }` replaces `BackgroundExportWriting` and `BackgroundQualityPhase`; `NamedPathMissing` carries only the path. `Ticket::kind()` names the job (`JobKind`), `App::job_is_current(ticket)` says whether its answer is still wanted, and `Job` is no longer public
- Opening a dataset has one owner, the loading controller (#458). `AppEvent::DoLoadScanPaths`, `DoLoadCsvWithParseStrings`, `DoDownloadHttp`, `DoDownloadS3ToTemp`, `DoDownloadGcsToTemp`, `DoLoadDownload`, `DoLoadSchema`, `DoLoadSchemaBlocking`, `DoLoadBuffer` and `DoDecompress` are gone: `Open` and `OpenLazyFrame` start the open's first phase, and each phase's answer starts the next. `LoadingState` and `PendingDownload` are gone; an export's progress is `ExportProgress`. `App::footer_progress` is a method returning the counter on screen: the open's while one is on its way, else the dataset's
- What an open finds is given to `DataTableState` once, as it is built: `with_open(OpenFacts { .. })` (#458). `set_remote_source`, `set_row_groups`, `set_file_row_groups`, `set_remote_files`, `set_remote_objects`, `set_dataset_schema` (now `OpenFacts::dataset: Option<DatasetAtOpen>`), `set_footers_pending`, `set_column_bytes`, `set_parquet_count_dir`, `set_measurements`, `set_open_notes`, `set_not_the_table` and `hold_download` are gone. A count found later lands through `count_landed`
- `App::awaiting_download_confirmation` is `awaiting_open_confirmation`, true for the question before a large read into memory too (#682)
- The `template` module is `view`: `Template` is `SavedView`, `TemplateManager` `ViewManager` and `Templates` `Views`. `QueryMode::Search` and `QStyle` are `Text` and `Q`, `InputType::Search` is `Query`, `AppEvent::Search`, `SqlSearch` and `FuzzySearch` are `QQuery`, `SqlQuery` and `TextQuery`, and `members::pick` no longer takes a format (#685)
